Apache Iggy's Kafka clients library implements Kafka's `Producer`, `Consumer` and `Admin` interfaces on top of Iggy. If your Java code is written against those interfaces, you change the constructor and the rest stays as it is.

That is the claim, so we tried it on seven real projects. This post walks through the simplest one, the Kafka examples that ship with Apache Kafka, so you can repeat it in about ten minutes. Then it covers the other six, and asks you to try it on your own code and tell us what breaks.

## What the library is

Three classes replace the three Kafka entry points:

```java
Producer<String, String> producer = new IggyKafkaProducer<>(props);   // was new KafkaProducer<>(props)
Consumer<String, String> consumer = new IggyKafkaConsumer<>(props);   // was new KafkaConsumer<>(props)
Admin admin = IggyAdminClient.create(props);                          // was AdminClient.create(props)
```

It is built for Java 17 against `kafka-clients` 4.3.0 and the Iggy Java SDK 0.10.0, for an Iggy 0.10.x server. It also runs with `kafka-clients` 3.9 on the classpath. It stores records the way the Iggy Kafka gateway does, so each can read what the other wrote. It is not in any Maven repository yet, so you build it from source.

## Try it: the Kafka examples on Iggy

You need Docker, JDK 17 or later, Maven and git.

### 1. Start Iggy

```bash
docker run -d --name iggy -p 18090:18090 \
  --cap-add SYS_NICE --security-opt seccomp=unconfined --ulimit memlock=-1:-1 \
  -e IGGY_ROOT_USERNAME=iggy -e IGGY_ROOT_PASSWORD=iggy \
  -e IGGY_TCP_ADDRESS=0.0.0.0:18090 -e IGGY_NODE_ADVERTISED_ADDRESS=localhost \
  -e IGGY_SHARDING_CPU_ALLOCATION=2 \
  apache/iggy:0.10.0
```

### 2. Build and install the library

```bash
git clone https://github.com/apache/iggy-demos.git
cd iggy-demos/kafka-clients
mvn -q install -DskipTests
cd ../..
```

### 3. Get Kafka's examples

The five classes that do not use transactions, from the 4.3.0 tag:

```bash
git clone -q --depth 1 --branch 4.3.0 --filter=blob:none --sparse https://github.com/apache/kafka.git
```

Three things changed, and each is small:

- The three constructors. The example held its client in a `KafkaProducer` or `KafkaConsumer` variable, so those variables became the `Producer` and `Consumer` interfaces. Code that already uses the interfaces does not need this.
- The Iggy password, which Kafka has no setting for. A password can also come from SASL/PLAIN.
- The address, now Iggy's port.

### 5. Run it

```bash
cd kafka-on-iggy
mvn -q compile exec:java -Dexec.mainClass=kafka.examples.KafkaConsumerProducerDemo -Dexec.args="1000 sync"
```

It creates a topic, sends 1000 records and reads them back. The run ends with:

```
consumer - Revoked partitions: [my-topic-0]
consumer - Fetched 1000 records
producer - Sent 1000 records
```

Drop `sync` to send asynchronously instead. Both modes pass in our test.

## Producers and consumers in six other projects

We made the same change to the Kafka producers and consumers in six open source projects:

- Apache Camel's Kafka component: producer and consumer
- Debezium Server's Kafka sink: producer
- Apache NiFi's Kafka connection service: producer and consumer
- The Flink Kafka connector's source: consumer
- Apache Pinot's Kafka plugin: consumer
- Zipkin's Kafka collector: consumer

Each change was the same as in the Kafka examples above: `KafkaProducer`, `KafkaConsumer` and `AdminClient` swapped for the Iggy classes, and the variables that held them typed to the Kafka interfaces. Camel did not even need that, because it lets you supply your own clients. Their own tests then passed against Iggy, apart from the few that need something Iggy does not do, such as transactions.

## What does not work

- Transactions and exactly-once. `initTransactions()` and the other transaction calls throw.
- Anything that depends on Kafka's exact error messages or exception types.
- Code that reads Kafka client internals by reflection.
- Anything Iggy has no equivalent for, such as truncating a partition. The Admin client throws `UnsupportedOperationException` for ACLs, quotas, SCRAM credentials and similar calls.
- Netty 4.1. The Iggy Java SDK 0.10.0 needs Netty 4.2, so if your project manages Netty at 4.1, import `netty-bom` 4.2.19.Final, the version the SDK uses.

The README has the full list of limits.

## Try it on your code

If your Java code uses `Producer`, `Consumer` or `Admin`, and not transactions, Kafka Streams or Connect, change the constructors and run your own tests against Iggy. That is the test we cannot run for you.

If something breaks, tell us. Open an issue at https://github.com/apache/iggy-demos/issues (the library is in `kafka-clients/`). Please include:

- the library commit and the `kafka-clients` version on your classpath
- the Iggy server version
- the project you ran it in and its version
- the failing call, with the stack trace
- the client properties you set, with passwords removed

A failure report is as useful to us as a pass.

The Kafka gateway is the other way to use Kafka clients with Iggy. It speaks the Kafka protocol, so nothing in the client changes except the address. That suits code you cannot change, clients in languages other than Java, and Kafka's own command line tools. See [Use Kafka tools with Apache Iggy](/blogs/2026/11/10/kafka-tools-with-iggy).
